Key Findings
1. False INSUFFICIENT_CONTEXT
Mistral returned INSUFFICIENT_CONTEXT despite explicit evidence in context — in the worst case ground_truth to context similarity was 0.9691 yet the model still refused to answer. Framework detects this via two-stage validation: if similarity ≥ 0.65, evidence exists → score 0.0 (not 1.0).
2. Claim Granularity — Enumeration Expansion
Evaluating a sentence with 5 items as one claim produces false positives. _expand_enumeration() splits 'X includes A, B, C' into atomic claims. Score changed from 1.0 → 0.6 for the same answer after this fix.
3. Semantic ≠ Factual — PUT vs PATCH
PUT vs PATCH yields cosine similarity 0.8337 — above the SUPPORTED threshold. Framework now applies technical conflict detection: if claim and evidence use different terms from the same group (HTTP methods, status codes), similarity is overridden to 0.0 regardless of embedding score.
4. Mistral is Faithful to Wrong Context
Distractor dataset: faithfulness dropped from 70.3% → 68.5%. When context said skip=5, limit=100, the model answered exactly that — ignoring that the correct values are skip=0, limit=10. Garbage in, garbage out. Retrieval quality fully determines answer quality.
5. Short Answer Blind Spot — Fixed in v1.2.2
'PUT' and '/files/...' previously scored 0.0 because the claim extractor produced 0 claims from single-token answers. Fixed: answers under the word threshold use an exact-match path (exact → substring → char similarity) instead of semantic similarity.
6. phi3:mini trades faithfulness for speed
Mistral: 70.3% avg faithfulness, 87s per case. phi3:mini: 76.2% avg faithfulness, 67s per case. phi3:mini over-generates — verbose but not precise. For development iteration, phi3:mini remains the pragmatic choice.

Acknowledged Limitations
  • Single embedding model. All similarity calculations use nomic-embed-text. Calibrated thresholds may need adjustment for other embedding models.
  • Small dataset. 10 clean cases, 5 distractor cases. Thresholds calibrated from limited observations — may need recalibration at scale.
  • Single domain. Only FastAPI documentation evaluated. Framework behavior on other technical domains not yet verified.
  • ROUGE-L sensitivity. Highly sensitive to stopwords and word order. Semantically identical answers with different structure will score low.
  • Short answer exact match not validated at scale. Implementation finalised in v1.2.2 — the char-similarity threshold was chosen empirically and needs more data to confirm.
